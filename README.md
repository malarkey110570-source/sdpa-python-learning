## Debugging Notes | 调试记录

Mistakes are intentionally kept as part of the learning process.

错误不是需要隐藏的内容，而是本仓库学习记录的一部分。

Some issues encountered so far:

```text
invalid character '（' (U+FF08)
```

Cause:

Chinese punctuation was used instead of English punctuation.

原因：

代码中误用了中文全角符号。

---

```python
if y ! = 0:
```

Incorrect because `!=` must be written together.

正确写法：

```python
if y != 0:
```

---

```python
if x = y:
```

Incorrect because `=` is assignment, not comparison.

正确比较应使用：

```python
if x == y:
```

---

Another important issue involved indentation:

```python
if x == y:
    print("x and y are equal")

    if y != 0:
        print(x / y)
```

The second condition only runs if the first condition is already true.

这帮助我进一步理解了：

> **Indentation is part of program logic in Python.**  
> **Python 的缩进不仅是格式，也是程序逻辑的一部分。**

---

A further issue involved comparing different data types:

```python
password = 1234
user_input = input("Password: ")

print(password == user_input)
```

Even when the user enters `1234`, the result is:

```text
False
```

because:

```text
password   → int
user_input → str
```

This reinforced the importance of understanding variable types.

这也进一步说明：调试时不能只看变量的“内容”，还要检查它的**数据类型**。

## Coding Style | 代码规范

I am gradually following **PEP 8** conventions and improving code readability.

目前正在逐步按照 PEP 8 改善代码规范和可读性。

Example:

```python
x = 5
y = 10

result = x + y
```

instead of:

```python
x=5
y=10
result=x+y
```

I am also trying to use variable names that describe their purpose.

例如：

```python
divisor
is_prime
total
number
```

instead of relying only on names such as:

```python
a
b
c
```

where a more meaningful name is possible.

Comments are used mainly when they explain the logic rather than simply repeat the code.

```python
# Check whether n has any divisor between 2 and n - 1
for divisor in range(2, n):
    ...
```

## How My Learning Has Changed | 学习方式的变化

### Week 01

The main question was:

> **What does this line of Python do?**

主要是在理解每一行语法是什么意思。

### Week 02

The questions are beginning to become:

> **Why does this branch execute?**  
> **How many times will this loop run?**  
> **What value does this variable hold after each iteration?**

现在开始更多关注程序运行过程和逻辑，而不是只关注单独一行代码。

For example:

```python
is_prime = True
```

initially looked unfamiliar because I thought `is_prime` might be a Python command.

After working through the example, I understood that it is simply a variable storing a Boolean value:

```text
True / False
```

这也是第二周一个很重要的理解：

> **Variables can represent program state, not only numbers or text.**

变量不仅可以保存数字和字符串，也可以保存程序当前的“状态”。
